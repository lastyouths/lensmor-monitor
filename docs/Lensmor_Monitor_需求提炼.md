# Lensmor Monitor 需求提炼与核心拆解

基于原始需求文档，将 Lensmor Monitor 的核心定位、功能模块与底层机制提炼如下，方便后续产品设计与开发参考。

## 1. 产品定位与愿景
- **产品定义**：一个自动化的**竞品情报监控平台**。
- **核心价值**：取代人工监控（浏览、截图、比对），用户只需配置目标，系统即可自动通过多渠道采集竞品信息（网站改版、定价、社媒舆情等），并利用 AI 输出结构化情报：**发生了什么变化、有何战略意图、下一步该怎么做**。

## 2. 核心功能模块

### 2.1 新用户引导 (Onboarding)
- **角色选择**：选择自身岗位（产品、市场、创始人等），以决定 AI 解读情报的视角。
- **自有产品画像**：录入自有产品 URL、受众、核心卖点与战略目标，为 AI 提供“我方视角”基准。
- **竞品导入**：系统根据 URL 自动推荐或用户手动输入，自动发现关联链接（子域名、文档站、定价页等）。

### 2.2 竞品监控管理
- **列表与状态**：监控中 / 已暂停 / 采集进行中。
- **管理能力**：添加/编辑竞品（支持最多 10 条关联 URL），支持暂停/恢复，以及**手动触发全量刷新**采集。

### 2.3 竞品概览 (Overview)
- **公司基本面**：成立时间、融资阶段、规模、细分市场、领英主页等（自动化补全）。
- **最新情报**：以时间线 (Timeline) 形式展示近期的重要变化。

### 2.4 情报收件箱 (Inbox) —— 核心交互区
- **双分类**：
  - **分析报告**：单次网站内容变化的具体分析。
  - **战略总结**：基于多条变更汇总出的长期（如90天）演进分析。
- **情报卡片内容**：
  - 标签与筛选：优先级（紧急/中等/低）、时间、竞品来源。
  - 核心展示：**发生了什么**、**战略意图**、**行动建议**（按优先级分级）及原始快照/站点链接。
  - 历史演变追踪：能够识别变更类型（营销、运营、功能、定价）及全盘战略演进。

### 2.5 情报反馈闭环
- **用户反馈**：对情报进行评价（有用 / 有误 / 不重要）。
- **错误分类**：不准确、不相关、过时、噪音等，用于持续优化 AI 的分析准确率。

## 3. 数据与 AI 引擎机制

### 3.1 采集与清洗
- **数据源**：网页快照抓取、社媒抓取（如 Reddit）、公司商业数据补全。
- **预处理**：HTML 转 Markdown、去噪、提取摘要。

### 3.2 AI 分析管道 (Pipeline)
1. **语义差异分析**：对比前后两次内容的有意义变更及影响面。
2. **长线演变分析**：串联多个时间点快照。
3. **社媒与情绪分析**：提炼公众讨论基调与风险信号。
4. **决策生成**：汇聚所有原子报告生成战略总结和执行建议。

## 4. 技术与架构要求

- **运行机制**：所有采集/分析任务均在后台**异步队列**中执行（支持排队、重试、取消）；支持定时 Cron 采集。
- **性能与体验**：首屏加载 <3秒，分页加载 <2秒，异步任务有实时状态反馈，空数据/异常状态有友好引导。
- **安全性**：用户数据（租户）隔离、登录认证、敏感文件（如快照截图）的签名链接访问、后台任务端点的鉴权保护。
- **关键第三方依赖**：
  - Auth 认证服务
  - AI 大语言模型（LLM）
  - 网页归档 / 浏览器自动化采集（对应工具链如 Wayback Machine, Jina AI）
  - 社媒抓取（如 Thordata）
  - 异步任务队列 / 数据库服务（如 Supabase）
