## 1. 结论摘要（先给结论）

- **一句话目标**：用最低成本、最高视觉冲击力验证“自动抓取竞品情报 + AI 深度分析 + 差异可视化”的产品价值。
- **本次 In / Out 的边界**：
  - **In**：输入 1 个竞品 URL -> 触发 Next.js 后台伪异步队列 -> 抓取真实页面 (降级 Mock) -> AI 分析生成带 Diff 与行动清单的报告 -> 前端高级感 Inbox 展示。
  - **Out**：复杂的多租户权限、角色定制、真异常重试队列、全自动的 Cron 调度（本次仅做手动触发触发后台异步模拟）。
- **推荐方案**：Next.js 全栈承载异步伪队列，真实数据+Mock降级保障演示，重仓前端“时间轴Diff与行动建议” UI。
- **优先验证点**：V-001 (Jina/Wayback 数据真实抓取可行性)

## 2. 推荐方案：Next.js 全栈极简+前端重现方案

- **方案名**：Next.js All-in-One 异步模拟方案
- **主流程 / 关键机制**：
  1. 用户在前端输入竞品 URL 并点击“生成分析”。
  2. 前端调用 API Route 写入 DB 一条 `status=pending` 记录并立即返回。
  3. API Route 触发后台逻辑（通过 `fetch` 自身或直接起 Promise）开始处理。
  4. 后台抓取数据（Wayback/Jina），喂给 LLM 生成差异和行动清单，更新 DB 状态。
  5. 前端轮询状态，完成后展示极具视觉冲击力的 Diff 卡片与行动 Checklist。
- **关键边界/取舍**：
  - 牺牲真正的分布式鲁棒性（重启进程可能丢任务），换取极速开发体验。
  - 强依赖前端 UI 表现力（shadcn/ui + framer-motion）来掩盖底层“伪异步”的简单。
  - 设定死限：外部抓取失败直接 Fallback 到 Mock 数据，确保演示绝对不会白屏。
- **为什么选它**：开发资源极度受限且为单兵作战，无需引入额外的后端部署流（如 Supabase Edge Functions）；又能完美欺盖演示需要的“异步”体感。

## 3. 备选方案

### 3.1 备选方案：全链路真实分布式架构

- **核心机制**：前端 Next.js -> Supabase DB -> 触发 Supabase Webhook -> Supabase Edge Function (Deno) 执行长耗时爬虫与 LLM -> 写回 DB。
- **主流程**：
  1. 用户提交 URL。
  2. Next.js 直接操作 Supabase。
  3. 数据库 Trigger 拉起边缘函数。
  4. 边缘函数内跑真实网络请求和流式 LLM。
- **边界与取舍**：完全解耦，架构最正规，但调试链路长。
- **适用前提**：团队后端资源充足，或者到了正式 MVP 阶段。
- **不选原因**：当前是 POC，时间紧任务重，多端部署与查日志的成本过高，容易偏离“验证核心视觉与逻辑”的目标。

## 5. 验证清单（V-xxx，可执行）

- **V-001 真实抓取链路可用性验证**
  - **风险/假设**：Jina Reader 或 Wayback Machine API 有反爬限制或网络阻塞，导致 POC 期间频频失败。
  - **方法**：在开发初期，抽 1-2 小时单独测试这两个接口对目标竞品站（如 Vercel, Supabase 主页）的读取稳定性。
  - **成功/失败信号**：若连续请求 3 次能稳定返回有效 Markdown，则成立；否则失败。
  - **Owner**：DEV
  - **截止**：开发第一天结束前
  - **触发动作**：不成立则果断切入 Fallback Mock 逻辑，不再浪费时间死磕爬虫。

- **V-002 Diff UI 渲染复杂度**
  - **风险/假设**：要把 Markdown 的 Diff（增删改）渲染成 GitHub 那样美观的视图非常耗时。
  - **方法**：调研现成的 React Diff 渲染库（如 `react-diff-viewer`）。
  - **成功/失败信号**：半小时内能跑通 Demo 则成立。
  - **Owner**：DEV
  - **截止**：开发 UI 阶段前
  - **触发动作**：不成立则降级为用两列卡片横向对比“Before / After”文本，不求细粒度词级别高亮。

## 8. Mini-PRD

- **MVP 范围**：
  - **In**：提供一个简单的输入框输入目标 URL；点击后展示加载状态；后台完成后页面更新；页面展示包含概览、Diff 差异视图、AI 行动建议清单的精美情报卡片。
  - **Out**：登录注册、历史报告管理、多竞品对比。
- **验收标准（AC）**：
  1. 用户输入有效 URL 并提交，页面无刷新进入“生成中”状态。
  2. 模拟/真实等待 5~15 秒后，出现情报卡片。
  3. 情报卡片内必须清晰展示“过去 vs 现在”的视图对比。
  4. 情报卡片底部必须有可以 Check 的行动建议 Checklist。
- **交互变化结论**：全新交互，偏单页应用 (SPA) 体验。
- **影响面**：新增 `app/page.tsx` 首页，新增 API Routes `/api/analyze`。
