# Lensmor Monitor POC 需求提炼与核心拆解

基于原始需求文档，将 Lensmor Monitor 的核心定位、功能模块与底层机制提炼如下，作为本次 POC（概念验证）的原始需求基准。

## 1. 产品定位与愿景
- **产品定义**：一个自动化的**竞品情报监控平台**。
- **核心价值**：取代人工监控（浏览、截图、比对），用户只需配置目标，系统即可自动通过多渠道采集竞品信息（网站改版、定价、社媒舆情等），并利用 AI 输出结构化情报：发生了什么变化、有何战略意图、下一步该怎么做。

## 2. 核心功能模块 (POC 关注范围)

### 2.1 新用户引导 (Onboarding)
- **角色选择**：选择自身岗位（产品、市场、创始人等），以决定 AI 解读情报的视角。
- **自有产品画像**：录入自有产品 URL、受众、核心卖点与战略目标，为 AI 提供“我方视角”基准。
- **竞品导入**：系统根据 URL 自动推荐或用户手动输入，自动发现关联链接（子域名、文档站、定价页等）。

### 2.2 竞品概览与监控
- **列表与状态**：监控中 / 已暂停 / 采集进行中。
- **最新情报**：以时间线 (Timeline) 形式展示近期的重要变化。

### 2.3 情报收件箱 (Inbox) —— 核心交互区
- **情报卡片内容**：
  - 标签与筛选：优先级（紧急/中等/低）、时间、竞品来源。
  - 核心展示：发生了什么、战略意图、行动建议（按优先级分级）及原始快照/站点链接。

## 3. 数据与 AI 引擎机制

### 3.1 采集与清洗
- **数据源**：网页快照抓取 (Wayback Machine / Jina)、社媒抓取 (Thordata)。
- **预处理**：HTML 转 Markdown、去噪、提取摘要。

### 3.2 AI 分析管道 (Pipeline)
- **语义差异分析**：对比前后两次内容的有意义变更及影响面。
- **社媒与情绪分析**：提炼公众讨论基调与风险信号。

## 4. 技术与架构要求
- **运行机制**：所有采集/分析任务均在后台异步队列中执行（支持排队、重试、取消）；支持定时 Cron 采集。
- **性能与体验**：首屏加载 <3秒，分页加载 <2秒，异步任务有实时状态反馈，空数据/异常状态有友好引导。
- **关键第三方依赖**：
  - 前端：Next.js 15 + Tailwind CSS v4 + Vercel
  - 后端/数据库：Supabase
  - AI 大语言模型（LLM）
  - 网页归档 / 提取：Wayback Machine, Jina AI
  - 社媒抓取：Thordata

## 澄清记录

- **本轮结论**：POC 的侧重点为“跑通端到端主流程主线”。角色选择、用户权限等边缘/支撑功能可轻拿轻放；重点保障“输入竞品 -> 采集与AI分析 -> Inbox展示”的故事闭环。
- **本轮新增/更新的约束**：暂不实现复杂的用户权限隔离与多租户角色定制体系。
- **关键决策**：采用端到端主线薄切片策略。
- **遗留歧义**：数据源（网页 vs 社媒）的具体优先级范围；定时自动抓取与手动抓取的实现深度。

- **本轮结论**：数据源范围：优先尝试对接真实外部数据（如 Wayback Machine / Jina），如果在 POC 阶段遇到阻塞，再降级使用 Mock 数据（写死的假 JSON）来保证主流程通畅。
- **本轮新增/更新的约束**：在数据对接上设定时间盒或失败退路，避免过度陷入爬虫反爬/接口限制中。
- **关键决策**：优先真实请求 -> 遇到阻力即刻 Mock。
- **遗留歧义**：用户触发采集的方式（自动还是手动）。

- **本轮结论**：演示触发机制采用“异步队列”模式。即前端输入 URL 后直接返回状态，后台（如利用 Supabase Functions 或简单的背景任务队列）异步执行采集和分析，完成后前端展示“分析报告”。
- **本轮新增/更新的约束**：必须实现一个能体现异步状态的前端交互（采集中/分析中/已完成）。
- **关键决策**：POC 即采用异步架构。
- **遗留歧义**：无。

- **本轮结论**：POC 需要具备强烈的表现力和亮点。我们将主打：
  1. **直观的视觉差异体验（类似时间轴/Diff 比对）**。
  2. **具有执行深度的 AI 建议（Actionable Checklist）**。
  3. 如果进度允许，加入简单的**情绪感知雷达/标签**增强冲击力。
- **本轮新增/更新的约束**：前端 UI 复杂度上升，需要寻找合适的组件库（如 shadcn/ui 结合 framer-motion）来快速堆叠“高级感”。
- **关键决策**：在“分析报告”详情页中，重仓表现层 UI，不只做文本罗列，要做结构化的卡片、比对图和行动按钮。
- **遗留歧义**：无。

- **本轮结论**：关于异步后端代码的位置，考虑到为了快速出结果且你一个人要在短时间内拿出一个高完成度的作品：**强烈建议采用 Next.js API Routes (Server Actions/Route Handlers) 作为承载**。对于 POC 而言，引入 Supabase Edge Functions 会增加部署心智负担与调试成本；直接在 Next.js 里做个轻量的、基于 DB 轮询的“伪异步”就能完美达到视觉上的异步效果（不阻塞前端）。
- **本轮新增/更新的约束**：使用 Next.js App Router API 模拟异步任务；用 DB 状态字段（pending -> processing -> completed）支撑前端流转。
- **关键决策**：架构做极简收敛，核心集中在“一个 Next.js 搞定一切展示与接口”。
- **遗留歧义**：无。
